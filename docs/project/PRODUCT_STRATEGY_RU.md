# Monte-Neo — продуктовая стратегия и план модернизации (2026-09)

> Внутренний документ. Статус: в работе. База: v0.17.7 → реализация начата в v0.18.0 (ядро верификатора, MCP, интеграции).

## 1. Честный диагноз текущего состояния

### Что реально есть (активы)

| Актив | Ценность |
|-------|----------|
| Fee-aware next-bar движок (`monte_neo.backtest`) | Правильная семантика: сигнал на t → исполнение на t+1, комиссии, slippage, SL/TP/trail, funding, сессии |
| Export API v1 + golden vectors | Машиночитаемый, версионируемый результат + воспроизводимость (`verify_export_golden`) |
| Анти-оверфит блок | `holdout_sma_sweep`, CSCV/PBO, walk-forward, noise/shuffle/sensitivity MC |
| `HeuristicPolicy` + JSONL-лог меток | Зародыш «судьи»: promote / MC / reject + корпус для будущего LocalScorer |
| Культура честности | «no peer names», честная таблица производительности, раскрытие того, что входит в таймеры |
| Дистрибуция | PyPI, CI, docs-сайт, MIT, 100% coverage-гейт |

### Что слабое (надо признать)

1. **Главный заявленный USP не работает.** «Скорость на Apple Silicon / Metal» — собственные замеры
   показывают, что Numba в 50–100× быстрее Metal на типичных сетках (docs/development/performance.md).
   Позиционирование «быстро на Mac» — узкое и неуникальное (Numba есть у всех).
2. **Стратегии = только SMA-кросс.** Пользователь не может принести *свою* стратегию в export-путь
   без написания кода под внутренний формат.
3. **Размытый фокус.** Генератор индикаторов, MLX 3D engine, paper OMS, адаптеры Binance/Bybit, CLI-мастер,
   экспорт в C++/Metal — много «полос», ни одна не доведена до «вау».
4. **Бэктестеров — тысячи.** В 2026 любой агент (Claude Code / Codex / Cursor) пишет векторный бэктест
   за 2 минуты. Уже есть MCP-серверы с бэктестами (tradingview-mcp и др.) и open-source «overfit detectors»
   (Deflated Sharpe, PBO, Reality Check). Код как таковой — не преимущество.

**Вывод:** продавать «ещё один бэктестер» бессмысленно. Ценность проекта — в *честности и проверяемости*
результата, а не в скорости.

## 2. Ниша: «Верификатор для AI-сгенерированных торговых стратегий»

### Проблема (реальная и растущая)

С 2026 года LLM-агенты массово генерируют стратегии «из текста в бэктест». Типичные ошибки агентов:

- **look-ahead** (`shift(-1)`, `close` того же бара как цена входа, нормализация по всему ряду, `center=True`);
- **нулевые комиссии / fantasy fills** (исполнение по close сигнального бара, игнор спреда и funding);
- **data snooping** (агент перебрал 300 вариантов и показал лучший — Sharpe 3.1, который после поправки ≈ 0);
- **survivorship / утечка через ресемплинг и таймзоны**;
- **«подгонка к тесту»** — агент итерирует, пока метрика не станет зелёной, и сообщает об успехе.

Агент не может сам себе быть судьёй: у него есть стимул «закрыть задачу». Нужен **независимый,
детерминированный, внешний оракул**, который агент *обязан* вызвать до того, как заявит результат.

### Позиционирование (одна фраза)

> **Monte-Neo — «CI для торговых стратегий»: независимый верификатор, который агенты (Claude Code, Codex,
> Gemini, Cursor) вызывают перед тем, как сказать «стратегия работает». Возвращает вердикт,
> список найденных обманов и воспроизводимый сертификат.**

Не «бэктестер», а **gate / аудитор / линтер честности**. Аналогии: `mypy` для кода, SSL-сертификат для сайтов,
«Codecov для бэктестов».

### Почему ниша защитима, если код дешёвый

Код повторить можно. Повторить сложно:

1. **Корпус ловушек (Trap Suite)** — сотни эталонных «плохих» стратегий с известным типом обмана
   (look-ahead, leakage, snooping…) + golden-ответы. Это данные, а не код; растут с каждым найденным багом.
   Это одновременно тест-сьют верификатора и **публичный бенчмарк агентов**.
2. **Стандарт и формат сертификата** — открытая спецификация `strategy-verdict v1` (JSON-schema) +
   подпись + хэш данных/кода. Кто первым станет «форматом по умолчанию», тот и держит нишу (network effect:
   сертификаты ссылаются на версию верификатора).
3. **Размеченные данные** — лог `append_research_label` → датасет «вердикт → что было в live/paper позже».
   Со временем это даёт калиброванный скоринг (LocalScorer B), которого нет у конкурентов.
4. **Доверие/бренд** — уже заложенная культура честности (honest perf, no-hype) — редкость в трейдинг-тулинге.
5. **Дистрибуция внутри агентов** — хуки/skills/плагины, которые встраивают проверку в процесс
   по умолчанию (агент не может «забыть» проверить).
6. **Публичный лидерборд «Agent Backtest Honesty Bench»** — какие модели/агенты чаще всего обманывают себя.
   Это маркетинг, который сам себя распространяет.

## 3. Продуктовая архитектура (целевая)

```
                ┌───────────────────────────────────────────────┐
  Агенты        │ Claude Code │ Codex │ Gemini CLI │ Cursor │ … │
                └──────┬───────────────┬────────────────┬───────┘
                       │ MCP (stdio/HTTP)│ CLI + JSON     │ Skills/Hooks/Rules
                ┌──────▼─────────────────▼────────────────▼──────┐
  Интерфейсы    │ monte-neo-mcp  │  monte-neo verify  │ GH Action │
                └──────┬─────────────────────────────────────────┘
                ┌──────▼─────────────────────────────────────────┐
  Ядро          │ Verifier: ingest → economics → checks → verdict│
                │  • Signal ingest (свои сигналы / код / Pine?)  │
                │  • Fee-aware next-bar (существующий движок)    │
                │  • Look-ahead probes (truncation/perturbation) │
                │  • Overfit: DSR, PBO/CSCV, holdout, WF, MC     │
                │  • Cost stress: break-even bps, delay scan     │
                │  • Policy → verdict + certificate              │
                └──────┬─────────────────────────────────────────┘
  Данные/доверие       Trap Suite · Golden vectors · Label log · Signed certificates
```

### 3.1 Ключевая новая фича: универсальный ingest сигналов

Сейчас export работает только для SMA. Нужно принимать:

- **массив позиций/сигналов** (`signals.parquet`/`npy` + OHLCV) — самый простой и универсальный путь;
- **Python-функцию** `def signal(df) -> Series` (запуск в песочнице);
- **сетку параметров** (для DSR/PBO нужно знать, *сколько* вариантов перебрано — агент обязан передать `n_trials`).

### 3.2 Look-ahead probes (главный «вау»-эффект)

Детерминированные тесты без чтения кода:

- **Truncation test:** считаем сигнал на `df[:t]` и на полном `df`; если `signal[t]` отличается → утечка из будущего.
- **Future-perturbation test:** шумим бары после `t`, сигнал до `t` не должен меняться.
- **Delay scan:** сдвиг исполнения на +1/+2 бара — если доходность «обрушивается», edge был в fill-timing.
- **Static AST lint** (уже есть `utils/ast_utils.py`): `shift(-k)`, `center=True`, fit-scaler на всём ряду.

Это то, что агент реально не сделает сам «по привычке», и то, что сразу показывает ценность.

### 3.3 Вердикт и сертификат

```json
{
  "schema": "strategy-verdict/1",
  "verdict": "REJECT",
  "reasons": ["lookahead:truncation_mismatch@bar 1832", "dsr=0.04 (n_trials=312)"],
  "metrics": {"sharpe": 2.9, "deflated_sharpe": 0.04, "pbo": 0.61, "breakeven_cost_bps": 1.8},
  "reproducibility": {"data_sha256": "…", "signal_sha256": "…", "engine": "monte-neo 0.18.0"},
  "next_actions": ["fix shift(-1) in feature 'ret_fwd'", "report n_trials honestly"]
}
```

Вердикты: `PASS` / `PASS_WITH_WARNINGS` / `NEEDS_MORE_EVIDENCE` / `REJECT`. `next_actions` пишутся так,
чтобы агент мог сам исправить код и перезапустить проверку (замкнутый цикл).

## 4. Интеграция с агентами (как сделать правильно)

Принцип: **одно ядро + тонкие адаптеры**. MCP — общий знаменатель (поддерживается Claude Code, Codex,
Gemini CLI, Cursor, ChatGPT-коннекторами). Остальное — упаковка.

| Платформа | Что поставляем | Механизм «обязательности» |
|-----------|----------------|---------------------------|
| **Claude Code** | MCP-сервер + plugin (skill `verify-strategy`, slash-команда `/verify`, hook) | `Stop`/`PostToolUse` hook: если в диффе есть бэктест и нет свежего сертификата → напомнить/блокировать |
| **Codex (OpenAI)** | MCP в `config.toml` + `AGENTS.md`-сниппет | Правило в AGENTS.md: «перед заявлением результата вызови `monte_neo.verify`» |
| **Gemini CLI** | MCP + extension (`gemini-extension.json`) + `GEMINI.md` | Контекст-файл с тем же правилом |
| **Cursor** | MCP + `.cursor/rules/*.mdc` | Always-apply rule для папок со стратегиями |
| **ChatGPT / Claude.ai** | Удалённый MCP (HTTP) — hosted tier | Для не-кодеров: «загрузи CSV сигналов → вердикт» |
| **CI** | GitHub Action `monte-neo/verify-action` | PR-комментарий с вердиктом; красный статус при REJECT |

MCP-инструменты (минимальный набор, не 30 штук — меньше = агент лучше выбирает):

1. `verify_strategy(ohlcv, signals|code, costs, n_trials)` → verdict + certificate
2. `probe_lookahead(ohlcv, code)` → утечки с номерами баров
3. `cost_stress(...)` → break-even bps, delay scan
4. `explain_verdict(certificate_id)` → человекочитаемое объяснение
5. `research_manifest()` → семантика движка (агент понимает правила до запуска)

## 9. Риски

| Риск | Митигирование |
|------|---------------|
| Крупный игрок (TradingView/QuantConnect) добавит такую же проверку | Быть открытым стандартом + нейтральным (не привязан к брокеру/данным); бенчмарк агентов — нейтральная площадка |
| Ложные REJECT раздражают | Вердикт с объяснением и `next_actions`; метрика FP на честных стратегиях — публичная |
| Юридически: «сертификат» ≠ инвестрекомендация | Явный disclaimer: проверяется методология, а не будущая прибыль |
| Выполнение чужого кода | Песочница (subprocess, без сети, лимиты), для hosted — изоляция контейнерами |
| Распыление снова | Правило: любая фича должна улучшать вердикт или дистрибуцию, иначе — нет |
